Annotation Guidelines Template

Sample instructions for AI training annotation projects.

Purpose

These guidelines demonstrate how to write clear, comprehensive instructions for human annotators working on AI training data. Shows ability to communicate evaluation criteria, handle edge cases, and establish quality standards.

Key Components of Good Guidelines

1. Clear Task Definition

What exactly is the annotator doing?

  • Read the user's message
  • Review the AI's response
  • Rate on 5 dimensions
  • Identify specific issues
  • Provide brief justification

2. Rating Scales with Examples

Each dimension needs concrete examples, not just definitions.

5 - Very helpful: Comprehensively addresses question, provides specific information, would fully resolve user's issue
4 - Helpful: Directly addresses question, provides most needed information
3 - Somewhat helpful: Answers incompletely, useful information but lacks important context
2 - Minimally helpful: Tangential to question, generic information
1 - Not helpful: Completely misunderstands or refuses inappropriately

3. Edge Cases & Tricky Situations

  • What if the user's request is unclear?
  • What if the user asked for something inappropriate?
  • What if you disagree with the AI's perspective?
  • What if you don't have enough context?

4. Quality Standards

  • Every field must be filled out
  • Ratings must be based on guidelines, not personal preference
  • Justifications must reference specific aspects
  • Don't overthink edge cases

Annotation Workflow

Step 1: Read the User Message

  • What is the user trying to accomplish?
  • What kind of response would actually help them?
  • Are there any implicit requirements?

Step 2: Read the AI Response

  • First impression: Does this help?
  • Read through completely before rating

Step 3: Rate Each Dimension

  • Use the full scale (don't cluster around 3-4)
  • Consider each dimension independently
  • Reference examples when uncertain

Step 4: Write Justification

Good justification: "Rating helpfulness as 2 because while it addresses the topic generally, it doesn't provide specific steps. User would still be stuck."

Bad justification: "Not very good. Rating: 2."

FAQs for Annotators

Q: What if I strongly disagree with the AI's opinion?

Rate based on quality and helpfulness, not agreement. If it's a topic with valid disagreement, the response can still score high if it's well-argued.

Q: What if the response is very long?

Yes, read all of it. Length doesn't automatically mean low quality, but check if it's justified or just padding.

Q: Can I rate 3.5?

No, use whole numbers only. If genuinely torn between two ratings, go with your gut and explain in the justification.

Q: What if I'm not sure about accuracy?

Mark "Accuracy uncertain" and note it. Don't mark something accurate just because it sounds right.

Skills This Demonstrates

  • Systems thinking: Designing guidelines that prevent ambiguity
  • Edge case handling: Anticipating what will confuse annotators
  • Quality assurance: Building in quality standards and spot-checks
